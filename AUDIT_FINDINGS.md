## Дополнительно исправлено

- Переключение режима формы стирало введённое название, суммы, дату и реквизиты. Черновик сохраняется, значения экранируются.
- Дата без времени исчезала; теперь время по умолчанию 23:59, часовой пояс вычисляется для выбранной даты (включая DST).
- Ссылка `startapp=new` не открывала создание. Шим исправляет структуру `initDataUnsafe.user` и действительно открывает ссылки.
- При 401 с подлинным initData интерфейс подставлял демонстрационный сбор. Теперь показывает ошибку авторизации.
- В закрытом сборе показывались кнопки оплаты/возврата/отмены, которые сервер отклонял.
- Ошибка `editMessageText` вызывала рассылку новых дублей карточки. Теперь неуспешное обновление не порождает новое сообщение и не попадает в кэш успехов.
- Удаление не убирало личные карточки участников. Теперь обрабатываются все известные cards и связанные ожидания ввода.
- Напоминание помечалось отправленным до ответа Telegram: при сбое его уже не повторяли. Отметка сохраняется после успеха.
- Долгое `getMe`/регистрация меню задерживали запуск HTTP и приводили к временным 502. HTTP начинает слушать до вызовов Telegram.
- Команды `...@other_bot` ошибочно исполнялись; неверные номера типа `-1` распознавались как 1.
- Новые ID приглашений содержат 128 случайных бит вместо 32; старые ссылки сохранены для совместимости.

## Проверки

```bash
python3 -m unittest discover -s tests -v
node tests/test_frontend.cjs
node --check public/app.js
git diff --check
```

Результат: **33 серверных теста + 9 сценариев JS прошли**. Тесты поднимают локальный
HTTP-сервер с подписанными initData трёх и более искусственных пользователей; каждый тест
использует отдельный временный DATA_DIR. Telegram API подменён, реальные сообщения не отправляются.
Дополнительно проверены настоящий процесс запуска и освобождение блокировки перед сетевым запросом.

На исходном `195ab3e` запуск первых 31 теста завершился ошибками (30 проваленных
проверок и 9 исключений, включая подслучаи тестов). Это регрессионные воспроизведения,
а не десять искусственно придуманных ошибок.

В Chrome на локальном сервере проверены: ссылка создания, переключение режима с сохранением
черновика, создание общей цели, оплата, отмена оплаты, отказ, возврат, редактирование.
Управление браузером зависло на нативном confirm закрытия. Закрытие и удаление проверены
через HTTP и команды в тестах; прохождение этих двух действий через UI не заявляется.

Все публичные HTTP-маршруты и зарегистрированные команды охвачены сценариями, но это
не доказательство отсутствия любых ошибок во всех сочетаниях. Физические клиенты Telegram
iOS/Android, реальная доставка сообщений и сбои ноды BotHost требуют проверки после выкладки.

## Совместимость и эксплуатация

Схема state.json и денежная единица (целые рубли) сохранены. Данные не мигрируются и не очищаются.
По умолчанию state остаётся в `/app/data`; DATA_DIR позволяет изолировать локальные тесты.
При повреждённом state сервер теперь остановится, сохранив повреждённый файл: восстановление
из проверенного бэкапа безопаснее молчаливой потери всех сборов.
Для URL статистики задайте случайный STATS_KEY длиной от 32 символов; `/stat` владельца работает без него.
Вход по initData старше суток требует повторного открытия Mini App.

Валидация HMAC и проверка auth_date сверены с [официальной документацией Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
